# OmniNode 组与批处理

## 组输入与组输出

在子树中建立带名称和类型的输入/输出接口，再放置组输入和组输出节点。组输出本身是输出终点，因此子树中只有能到达组输出的分支会执行。

接口拥有稳定 ID。重命名通常可以保留引用；删除接口或改变类型后，父树中的旧连线和默认值仍然需要人工检查。

## 组引用

在父树放置“组引用”，选择目标 OmniNodeTree 后，节点会同步目标树公开的输入与输出。节点上的跳转按钮可以进入子树，返回按钮回到 HoTools 维护的上一级。

不要让树直接或间接引用自身。循环引用没有有效的拓扑执行顺序，会在编译阶段失败。

## 组批量

“组批量”同样选择一棵子树，但只把其中一个公开输入设为批入口。该 Socket 显示为多输入方口，每个接入项会独立调用一次子树；其他输入在每次调用中保持相同。

批入口通过“Batch Input Index”选择，切换后节点会重建 Socket。输出按每次调用的顺序收集；批入口没有任何项时不会凭空执行一次默认调用。

> 批处理项之间不要依赖隐含先后状态。一个项目失败会让整棵根树本轮执行失败，本轮待提交缓存也不会保存。

## 缓存隔离

同一个子树被多个组引用，或在组批量中执行多次时，Runtime Cache 会按调用路径和批处理项隔离。相同 Cache Key 在不同实例中不会自然串值。

需要跨批次共享的数据应由父树明确传入，不要尝试用不断变化的 Key 绕过隔离。

# OmniNode 执行、调试与缓存

## 编译与运行

“编译运行”适合修改完图以后直接测试；“编译”与“运行”分开时，可以确认结构只编译一次，再反复运行同一份结果。

节点、连接、组接口或其他影响执行合同的内容变化后应重新编译。只修改普通运行输入时通常可以继续复用缓存；结果明显仍像旧图时，先清编译再编译，不要用清运行缓存代替。

## 每帧运行

打开后，节点树会在 Blender 完成帧切换后运行。每帧图应尽量只更新已有数据，不要在每一帧重复创建对象、材质、修改器或数据层。

物理解算依赖连续帧；跳帧、回退和播放循环可能触发内部重建。普通自动化图如果不需要时间状态，不应为了方便一直开着每帧运行。

## 调试

- 打印编译日志：只在编译或重编译时输出完整编译过程与寄存器桥。
- 编译流程可视化：在节点上静态显示实际编译顺序，绿色为普通节点，蓝色为 Always Run 节点。
- 运行追踪日志：每次运行都打印完整 IR 指令过程；每帧模式下输出量非常大。
- 运行时长统计：在控制台按间隔聚合执行和 IR Step 耗时。
- 显示节点运行计时：低频采样并把单次耗时显示在节点顶部，复杂节点还会显示内部阶段。

错误节点会变色并保存错误内容。修好输入或连接以后重新编译运行，确认错误标记已经消失；只看控制台最后一行容易错过真正出错的上游节点。

## 编译缓存与运行缓存

编译缓存保存“这张图怎么执行”；运行缓存保存“上一次执行留下的状态”。前者在图结构变化后重建，后者用于软跟随、漂浮、物理和用户 Cache 节点等跨帧逻辑。

“清编译”不会替代状态重置，“清缓存”也不会让错误图自动重新编译。排查时先判断自己要清的是执行结构还是跨帧状态。

## Runtime Cache

- 缓存读取：读取当前执行实例已经提交的值，同时输出是否命中。
- 缓存写入：本轮先暂存，只有整棵根树成功结束后才提交。
- 缓存删除：按名称删除，或清空当前 root/group/batch 实例的命名空间。
- 缓存调试：输出当前已提交状态叠加本轮待写入/待删除后的快照。

执行失败时，本轮普通写入和删除都不会提交。缓存名留空时会使用节点自己的运行时 ID；手工命名时应保持有限、稳定，不要把当前时间或每帧随机值直接当 Key。

Runtime Cache 不是保存到 `.blend` 的永久数据，重启 Blender 后不能依赖它仍然存在。

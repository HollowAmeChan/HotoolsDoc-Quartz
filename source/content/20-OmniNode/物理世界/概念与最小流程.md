# 物理世界概念与最小流程

## 四个阶段

1. 范围：从集合或场景收集物理对象，也可以进一步限制对象范围。
2. 帧开始：创建本帧物理上下文，读取声明和上一帧状态。
3. 解算：运行一个或多个 MC2、SpringBone VRM 或 Jolt 刚体域。
4. 帧提交：统一提交本帧命令和结果，再交给结果、写回、调试或烘焙节点。

## 生命周期节点

- 物理对象-从集合。
- 物理对象-从场景。
- 物理对象范围。
- 物理世界-帧开始。
- 物理世界-帧提交。
- 物理世界-结果流。

## 最小图

创建“从集合 -> 对象范围 -> 帧开始 -> 一个解算器模拟步 -> 帧提交 -> 结果流/写回”的最小图。输出节点应放在提交或后续消费结果的节点上，未连接到输出的解算分支不会执行。

## 时间与连续性

物理解算依赖连续帧和稳定输入。跳帧、回退、对象拓扑变化、参数结构变化或缓存被清理时，解算器可能需要重建状态。每个解算器页面必须记录自身的重置条件。

## 多解算器

物理世界允许在同一帧组织多个声明域，但执行顺序、共享碰撞和写回冲突必须通过实际图明确。文档示例先保持一个域一个最小图，再增加组合示例。

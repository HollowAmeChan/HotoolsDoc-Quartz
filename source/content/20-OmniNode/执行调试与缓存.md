# OmniNode 执行、调试与缓存

## 手动执行与每帧执行

补写执行当前树、停止执行、每帧运行开关和执行上下文。每帧图应保持幂等，避免每一帧重复创建对象、材质或数据层。

## 编译缓存

节点图会先编译为运行结构，再执行。图结构或相关接口变化时会重新编译；普通逐帧运行会复用缓存。补写手动重建/清理按钮和何时需要使用。

## Debug 编译与运行

- Debug 编译：查看节点图如何转为可执行指令。
- Debug 运行：记录节点级结果和错误。
- Debug 运行时长：记录节点或阶段耗时。

错误节点会变色并显示详情。修复输入或图结构后重新执行，并确认错误状态被清除。

## 帧级计时

性能面板区分 HoTools handler 时间和 Blender 引擎/重绘时间。先判断瓶颈属于节点执行还是依赖图、修改器和视口更新，再决定优化方向。

## Runtime Cache

跨帧临时状态必须显式通过 Cache Read、Cache Write、Cache Delete 和 Cache Dump 等图结构节点维护。Cache 不是写入 `.blend` 的永久数据，重启 Blender 后不应依赖它仍存在。

### 关键规则

- Read 读取上一次成功执行后提交的值。
- Write 在启用时暂存本轮新值，成功结束后才提交；关闭时只透传。
- Delete 可删除一个 key 或清空当前执行实例命名空间。
- Dump 用于检查当前实例的缓存快照。
- 执行失败时，待提交的普通写入和删除不会提交。
- 组和批处理会隔离缓存命名空间；仍应设计有限且稳定的 key，并提供清理路径。
